# bium (비움)

맥에서 안전하게 지울 수 있는 것만 찾아 디스크 공간을 되찾는 CLI 도구입니다.

## 이름

**비움** — 비어 있는 상태가 아니라, 비우는 행위를 뜻합니다.

"Mac Cleaner", "Mac Optimizer" 같은 뻔한 이름을 피한 건 의도적입니다. 그 작명은
macOS 스케어웨어의 패턴입니다 — 없는 문제를 만들어내 결제를 유도하는 부류요. 찾은 것을
부풀리지 않는 것이 설계 전체의 목표인 도구가 그 간판을 달 이유는 없습니다.

## 언어

기본은 영어입니다. `LANG`/`LC_ALL` 이 `ko` 로 시작하면 한국어로 나오고,
`BIUM_LANG=ko` 로 이 도구만 따로 지정할 수도 있습니다.

의존성이 없습니다. Xcode 없이 Command Line Tools + Swift 6.1 만으로 빌드됩니다.

```
bium scan             # 조사만 (아무것도 지우지 않음)
bium clean --dry-run  # 무엇이 지워질지 미리보기
bium clean            # SAFE 등급만, 휴지통으로 이동
bium empty-trash      # 여기서 실제 공간이 회수됩니다
```

## 설계 원칙

**기본값은 절대 사용자 데이터를 건드리지 않습니다.** 모든 규칙에 안전 등급이 붙어 있고,
`clean`의 기본 동작은 SAFE 등급뿐입니다. 그 위로 올라가려면 `--level` 을 직접 지정해야 합니다.

| 등급 | 뜻 | 예시 |
|---|---|---|
| `SAFE` | 기기가 알아서 다시 만듭니다. 시간만 들고 데이터는 잃지 않습니다. | 빌드 캐시, 등록되지 않은 에디터 확장, 브라우저 캐시 |
| `REVIEW` | 거의 확실히 버려도 되지만 내용이 사람마다 다릅니다. | 모델 가중치 캐시, 구버전 IDE 설정, pnpm 저장소 |
| `CAUTION` | 실제 사용자 데이터이거나 다시 만들기 비쌉니다. 규칙을 콕 집어야 지워집니다. | iPhone 백업, 오래된 다운로드, Docker 디스크 이미지 |

**되돌릴 수 있게 지웁니다.** 기본은 휴지통 이동(`trashItem`)입니다. 확인한 뒤
`empty-trash` 로 비워야 실제로 공간이 돌아옵니다. 급하면 `--permanent` 로 즉시 삭제할 수
있지만 복구는 불가능합니다.

**모든 실제 삭제는 기록됩니다.** `~/Library/Application Support/bium/logs/` 에
JSON으로 남습니다.

## 안전장치

삭제 직전에 — 스캔 시점이 아니라 — 모든 경로를 다시 검증합니다. 스캔과 삭제 사이에
심볼릭 링크가 바뀌었거나, `--only` 로 손수 지정한 경로가 이상하거나, 규칙에 버그가 있어도
여기서 걸립니다.

- 홈 디렉터리 밖은 삭제하지 않습니다. `/Library/Caches` 같은 시스템 영역은 root 권한이
  필요하므로 의도적으로 범위 밖입니다.
- `~`, `~/Library`, `~/Documents`, `~/.ssh` 등 보호 경로는 그 자체로는 절대 삭제되지
  않습니다 (안쪽 항목은 규칙에 따라 삭제될 수 있습니다).
- 이름이 `.git` / `.hg` / `.svn` 인 디렉터리는 어디에 있든 삭제하지 않습니다.
- 각 규칙이 선언한 루트 밖으로 나가면 거부합니다. 심볼릭 링크로 우회하는 것도
  부모 경로를 실제로 해석해 막습니다.
- 마운트 지점(외장 디스크, 네트워크 볼륨)은 건너뜁니다.

## 전체 디스크 접근 권한

macOS 는 `~/.Trash`, Safari 캐시, iOS 백업 같은 위치를 TCC 로 막아둡니다. 권한이 없으면
디렉터리를 읽는 것 자체가 거부되는데, 이때 "빈 디렉터리" 와 "읽을 수 없는 디렉터리" 는
API 상 구분이 되지 않습니다.

이 도구는 그 둘을 구분해서 보고합니다. 읽을 수 없는 위치는 조용히 빠지지 않고
`scan` 의 "검사하지 않은 규칙" 목록과 `doctor` 에 이유와 함께 나타납니다. 공간이
이미 회수된 것처럼 보이게 만드는 것이 실제 손실보다 나쁠 수 있기 때문입니다.

권한을 주려면 **시스템 설정 > 개인정보 보호 및 보안 > 전체 디스크 접근 권한** 에
사용하는 터미널 앱을 추가하세요. 휴지통만 비우면 되는 경우라면 Finder 에서 직접
비우는 편이 간단합니다.

## 용량 계산

숫자가 정직해야 의미가 있으므로 두 가지를 지킵니다.

- **할당된 블록**을 셉니다(논리 크기가 아니라). `df` 가 실제로 바뀌는 값입니다.
- **하드링크는 한 번만** 셉니다. pnpm 저장소와 Homebrew 셀러는 하드링크 덩어리라,
  순진하게 세면 회수 가능한 공간이 몇 배로 부풀려집니다.

디렉터리 순회는 `fts(3)` 기반이며 심볼릭 링크를 따라가지 않습니다.

## 규칙이 겹칠 때

구체적인 규칙이 일반 규칙보다 먼저 경로를 선점합니다. 예를 들어 `~/.cache/huggingface`
(REVIEW)는 `~/.cache` 전체 스윕(SAFE)보다 먼저 자기 경로를 가져가므로, `--level safe`
실행이 모델 가중치를 끌고 가지 않습니다. 선점 검사는 조상·자손 양방향으로 동작합니다.

## 위임 작업

파일을 직접 지우는 것보다 해당 도구에 맡기는 편이 안전한 것들은 명령으로 실행합니다.
스캔 목록에서 `▸` 로 표시됩니다.

| 규칙 | 실행하는 것 |
|---|---|
| `action-tm-snapshots` | `tmutil thinlocalsnapshots` — APFS 로컬 스냅샷. '사용 가능' 용량에 안 잡히는 공간의 가장 흔한 원인입니다 |
| `action-simctl-unavailable` | `xcrun simctl delete unavailable` — 못 쓰는 시뮬레이터 기기 |
| `action-brew-cleanup` | `brew cleanup --prune=all` |
| `action-docker-prune` | `docker system prune -a` |

해당 명령이 설치돼 있지 않으면 규칙은 조용히 빠지지 않고 "검사하지 않음" 으로 보고됩니다.

## 자주 쓰는 사용법

```sh
bium scan -v                    # 경로까지 전부 표시
bium scan --deep                # 오래된 node_modules / 빌드 산출물까지 (느림)
bium doctor                     # 디스크 현황 + 홈에서 큰 곳
bium list                       # 전체 규칙과 등급

bium clean --level review       # REVIEW 등급까지
bium clean --only npm-cache,gradle-cache
bium clean --exclude trash
bium scan --json                # 기계가 읽는 출력
```

## 빌드

```sh
swift build -c release
swift run bium-tests            # 테스트
./Scripts/install.sh                  # ~/.local/bin 에 설치
```

테스트는 `.testTarget` 이 아니라 평범한 실행 파일입니다. XCTest 와 swift-testing 은 둘 다
Xcode 에만 들어 있어서, Command Line Tools 만 있는 환경에서는 그 방법으로는 테스트를
아예 돌릴 수 없기 때문입니다.

## 다루지 않는 것

- 홈 밖 (`/Library`, `/Applications`, `/opt/homebrew`) — root 권한이 필요합니다.
  `doctor` 가 크기만 알려줍니다.
- 중복 파일 찾기, 대용량 파일 브라우저 — 범위 밖입니다.
- 설치된 앱 삭제 — 범위 밖입니다.
