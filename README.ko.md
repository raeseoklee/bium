# bium (비움)

맥에서 확보할 수 있는 디스크 공간을 찾아내는 명령줄 도구입니다. 하드링크를 한 번만
계산하고, 추측으로 판단하지 않으며, 읽을 권한이 없었던 디렉터리는 비어 있다고 보고하는
대신 읽지 못했다고 알려 줍니다.

```sh
brew install raeseoklee/tap/bium
```

탭이 사전 빌드된 유니버설 바이너리(arm64 와 x86_64)를 배포하므로, 설치할 때 Swift
도구 모음이 필요하지 않습니다. 소스에서 직접 빌드하는 경우에도 명령줄 도구(Command Line
Tools)와 Swift 6.1 만 있으면 되고, 어느 쪽이든 Xcode를 설치할 필요는 없습니다.

```sh
bium scan             # 조사만 수행하며 아무것도 삭제하지 않습니다
bium clean --dry-run  # 무엇이 삭제될지 미리 보여 줍니다
bium clean            # SAFE 등급만 휴지통으로 옮깁니다
bium empty-trash      # 이 단계에서 실제 공간이 회수됩니다
```

## 이름의 유래

**비움**은 비어 있는 상태가 아니라 비우는 행위를 가리키는 말입니다.

"Mac Cleaner"나 "Mac Optimizer" 같은 흔한 이름을 의도적으로 피했습니다. 그러한 작명은
macOS 스케어웨어가 사용하는 방식이기 때문입니다. 스케어웨어는 존재하지 않는 문제를
발견한 것처럼 표시한 다음, 그 문제를 해결해 주겠다면서 결제를 유도합니다. 발견한 내용을
과장하지 않는 것이 설계의 목표인 도구가 그러한 이름을 사용할 이유는 없다고 판단했습니다.

## 이 도구가 다르게 하는 것

비슷한 도구가 이미 많습니다. 다음 세 가지는 다른 도구에서 보기 어렵습니다.

**읽지 못한 위치를 알려 줍니다.** macOS는 `~/.Trash`와 Safari 캐시, iOS 백업 같은 위치를
전체 디스크 접근 권한으로 보호합니다. 권한이 없으면 디렉터리를 읽는 작업 자체가 거부되는데,
일반적인 API로는 "비어 있는 디렉터리"와 "읽지 못한 디렉터리"를 구분할 수 없습니다. 대부분의
도구는 이 상황에서 용량을 0으로 보고합니다. `bium`은 두 경우를 구분해서 이유와 함께
표시합니다.

```
검사하지 않은 규칙 4개:
  trash          읽을 수 없음(전체 디스크 접근 권한 필요): /Users/you/.Trash
  safari-cache   읽을 수 없음(전체 디스크 접근 권한 필요): /Users/you/Library/Caches/com.apple.Safari
```

공간이 이미 회수된 것처럼 보이게 만드는 결과는, 애초에 확인하지 않는 것보다 더 나쁠 수
있다고 보았습니다.

**표시하는 용량이 실제 값입니다.** 파일의 논리적 크기가 아니라 할당된 블록을 기준으로
계산하며, 하드링크는 한 번만 계산합니다. pnpm 저장소와 Homebrew 셀러는 대부분 하드링크로
구성되어 있어서, 이를 구분하지 않고 단순히 합산하면 회수 가능한 공간이 실제보다 몇 배로
크게 표시됩니다.

**추측하지 않고 에디터의 기록을 근거로 삼습니다.** 사용하지 않는 에디터 확장을 찾을 때,
버전 번호를 비교하는 방식 대신 에디터가 직접 관리하는 설치 목록인 `extensions.json`을
읽습니다. 이 목록에 없는 디렉터리만 삭제 대상으로 제안합니다. 이 도구를 만든 맥에서는
`~/.vscode/extensions` 안에 디렉터리가 145개 있었지만, 실제로 설치된 확장은 45개뿐이었습니다.

## 안전 등급

`clean` 명령은 기본적으로 SAFE 등급만 처리합니다. 그보다 높은 등급을 삭제하려면 `--level`
옵션을 직접 지정해야 합니다.

| 등급 | 의미 | 예시 |
|---|---|---|
| `SAFE` | 기기가 다시 만들어 냅니다. 시간이 걸릴 뿐 데이터를 잃지 않습니다. | 빌드 캐시, 등록되지 않은 에디터 확장, 브라우저 캐시 |
| `REVIEW` | 대부분의 경우 삭제해도 되지만, 내용은 사용자마다 다릅니다. | 모델 가중치 캐시, 구버전 IDE 설정, pnpm 저장소 |
| `CAUTION` | 실제 사용자 데이터이거나 다시 만드는 비용이 큽니다. 규칙을 직접 지정해야만 삭제됩니다. | iPhone 백업, 오래된 다운로드, Docker 디스크 이미지 |

삭제한 항목은 기본적으로 휴지통으로 이동하므로, `empty-trash` 명령을 실행하기 전까지는
되돌릴 수 있습니다. `--permanent` 옵션을 사용하면 휴지통을 거치지 않고 즉시 삭제하며, 이
경우에는 복구할 수 없습니다. 실제로 삭제한 내역은 모두
`~/Library/Application Support/bium/logs/` 에 JSON 형식으로 기록됩니다.

## 안전장치

경로는 조사한 시점이 아니라 삭제하기 직전에 다시 검증합니다. 조사와 삭제 사이에 심볼릭
링크가 변경되었거나, `--only` 옵션으로 직접 지정한 경로에 문제가 있거나, 규칙 자체에 결함이
있더라도 이 단계에서 거부됩니다.

- 홈 디렉터리 밖에 있는 항목은 삭제하지 않습니다. `/Library/Caches` 같은 시스템 영역은
  root 권한이 필요하므로 의도적으로 범위에서 제외했습니다.
- `~` 와 `~/Library`, `~/Documents`, `~/.ssh` 같은 보호 경로는 그 자체로는 삭제되지
  않습니다. 다만 그 안에 있는 항목은 규칙에 따라 삭제될 수 있습니다.
- 이름이 `.git` 이나 `.hg`, `.svn` 인 디렉터리는 어느 위치에 있든 삭제하지 않습니다.
- 각 규칙이 선언한 최상위 경로를 벗어나는 항목은 거부합니다. 심볼릭 링크를 이용해서
  우회하는 경우도 상위 경로를 실제로 해석해서 차단합니다.
- 외장 디스크나 네트워크 볼륨 같은 마운트 지점은 처리하지 않습니다.

## 언어 설정

기본 언어는 영어입니다. `LANG` 이나 `LC_ALL` 환경 변수가 `ko` 로 시작하면 한국어로
출력하며, `BIUM_LANG=ko` 를 지정하면 이 도구의 언어만 따로 바꿀 수 있습니다. 지원하지 않는
로케일을 만나면 일부만 번역된 화면을 보여 주는 대신 영어로 출력합니다.

환경 변수가 하나도 없으면 시스템 언어 설정을 따릅니다. 이 동작은 앱에서 특히 중요합니다.
Finder나 Dock에서 실행하면 LaunchServices를 거치는데, 이때 `LANG` 이 전혀 전달되지 않기
때문입니다. 이 대비책이 없으면 시스템이 한국어로 설정된 기기에서도 창이 영어로 표시됩니다.
환경 변수를 지정한 경우에는 언제나 그쪽이 우선합니다.

규칙의 식별자(id)는 모든 언어에서 영어로 고정되어 있으므로, `--only` 와 `--exclude` 옵션,
그리고 JSON 출력은 언어 설정과 무관하게 스크립트에서 사용할 수 있습니다.

## 위임 작업

파일을 직접 삭제하기보다 해당 도구에 맡기는 편이 안전한 작업은 명령을 실행하는 방식으로
처리합니다. 조사 결과 목록에서 `▸` 표시가 붙습니다.

| 규칙 | 실행하는 명령 |
|---|---|
| `action-tm-snapshots` | `tmutil thinlocalsnapshots` 를 실행합니다. APFS 로컬 스냅샷은 '사용 가능' 용량에 잡히지 않는 공간을 차지하는 가장 흔한 원인입니다 |
| `action-simctl-unavailable` | `xcrun simctl delete unavailable` 을 실행해서 사용할 수 없는 시뮬레이터 기기를 삭제합니다 |
| `action-brew-cleanup` | `brew cleanup --prune=all` 을 실행합니다 |
| `action-docker-prune` | `docker system prune -a` 를 실행합니다 |

해당 명령이 설치되어 있지 않으면 규칙을 목록에서 제외하지 않고 "검사하지 않음" 으로
보고합니다.

## 규칙이 겹치는 경우

더 구체적인 규칙이 일반적인 규칙보다 먼저 경로를 선점합니다. 예를 들어 REVIEW 등급인
`~/.cache/huggingface` 는 SAFE 등급인 `~/.cache` 전체 조사보다 먼저 자기 경로를 가져가므로,
`--level safe` 로 실행해도 모델 가중치를 함께 삭제하지 않습니다. 선점 여부는 상위 경로와
하위 경로 양쪽 방향으로 모두 검사합니다.

## 전체 디스크 접근 권한

`~/.Trash` 와 Safari 캐시, iOS 백업을 읽으려면 전체 디스크 접근 권한이 필요합니다.
**시스템 설정 > 개인정보 보호 및 보안 > 전체 디스크 접근 권한** 에서 사용하는 터미널 앱을
추가하면 됩니다. 휴지통만 비우면 되는 상황이라면 Finder에서 직접 비우는 편이 간단합니다.
어느 쪽을 선택하든 `bium` 은 처리하지 못한 위치와 그 이유를 함께 알려 줍니다.

## 자주 묻는 질문

**파일을 지웠는데도 디스크가 여전히 가득 찼다고 표시됩니다.**
대개 APFS 로컬 스냅샷이 원인입니다. 스냅샷은 '사용 가능' 용량으로 잡히지 않는 공간을
차지합니다. `bium doctor` 로 확인할 수 있고,
`bium clean --only action-tm-snapshots --level review` 를 실행하면 `tmutil` 이 스냅샷을
정리합니다.

**`~/Library/Developer/Xcode/DerivedData` 를 삭제해도 괜찮습니까?**
괜찮습니다. 빌드 중간 산출물과 인덱스이므로 다음 빌드가 한 번 느려질 뿐입니다. 이 도구에서
SAFE 등급으로 분류합니다.

**`~/.vscode/extensions` 가 왜 이렇게 큽니까?**
확장을 업데이트할 때 VS Code가 이전 버전을 항상 삭제하지는 않으며, 설치가 중단되면 UUID
형식의 이름을 가진 임시 디렉터리가 남습니다. `bium` 은 이 디렉터리를 `extensions.json` 과
대조해서, 에디터가 더 이상 참조하지 않는 항목만 삭제 대상으로 제안합니다.

**`brew cleanup` 이 알려 주는 용량만큼 실제로 확보됩니까?**
`bium` 은 Homebrew가 보고하는 값을 사용하되 하드링크를 한 번만 계산해서 표시하므로,
화면에 나오는 값은 `df` 명령의 결과가 실제로 변하는 크기와 일치합니다.

## 자주 사용하는 명령

```sh
bium scan -v                    # 모든 항목의 경로를 표시합니다
bium scan --deep                # 프로젝트 트리를 탐색해서 오래된 node_modules 와 빌드 산출물도 찾습니다 (느립니다)
bium doctor                     # 디스크 현황과 홈 디렉터리에서 큰 위치를 요약합니다
bium list                       # 모든 규칙과 안전 등급을 표시합니다

bium clean --level review       # REVIEW 등급까지 포함해서 정리합니다
bium clean --only npm-cache,gradle-cache
bium clean --exclude trash
bium scan --json                # 기계가 읽을 수 있는 형식으로 출력합니다
```

## 앱

명령줄 도구와 함께 SwiftUI로 만든 앱도 있습니다. 같은 규칙과 같은 안전 등급을 보여 주며,
SAFE 등급은 미리 선택되어 있고 그보다 높은 등급은 직접 선택해야 합니다. 명령줄에서
`clean` 이 동작하는 방식과 같습니다.

```sh
./Scripts/build-app.sh     # dist/Bium.app 을 조립합니다
open dist/Bium.app
```

Xcode 대신 스크립트로 번들을 조립하므로, 명령줄 도구만 있어도 프로젝트를 빌드할 수
있습니다. `Scripts/make-icon.sh` 는 1024×1024 PNG를 `Resources/AppIcon.icns` 로 변환하고,
그 PNG는 `Scripts/DrawIcon.swift` 가 그립니다.

## 소스에서 빌드하는 방법

```sh
swift build -c release
swift run bium-tests            # 384건의 검증을 실행합니다
./Scripts/install.sh            # ~/.local/bin 에 설치합니다
```

릴리스에 포함되는 유니버설 바이너리를 직접 만들려면 아키텍처별로 빌드한 다음 합쳐야
합니다. `swift build --arch` 옵션은 Xcode에 포함된 xcbuild를 필요로 하기 때문입니다.

```sh
swift build -c release --triple arm64-apple-macosx
swift build -c release --triple x86_64-apple-macosx
lipo -create -output bium .build/{arm64,x86_64}-apple-macosx/release/bium
codesign --force --sign - bium
```

테스트는 `.testTarget` 이 아니라 일반 실행 파일로 만들었습니다. XCTest와 swift-testing이
모두 Xcode에만 포함되어 있어서, 명령줄 도구만 설치한 환경에서는 그 방식으로 테스트를 실행할
수 없기 때문입니다.

## 이 도구가 하지 않는 것

- 홈 디렉터리 밖에 있는 항목은 처리하지 않습니다. `/Library` 와 `/Applications`,
  `/opt/homebrew` 는 root 권한이 필요하므로, `doctor` 명령이 용량만 알려 주고 그 이상은
  다루지 않습니다.
- 중복 파일을 찾거나 큰 파일을 탐색하는 기능은 제공하지 않습니다.
- 설치된 애플리케이션을 삭제하지 않습니다.
- 파일을 iCloud로 옮기지 않습니다. 그 작업은 macOS의 '저장 공간 최적화' 기능이 담당하며,
  `bium` 은 파일을 삭제합니다.
